# Update fields — WoW Classic 3.4.3.54261

Generated by `tools/updatefields.py` from the client's own deserializers (run under emulation); do not edit by hand. The machine-readable form is `updatefields.json`. The SMSG_UPDATE_OBJECT framing around these payloads is in [updateobject.md](updateobject.md).

## Which system

3.4.3 uses the modern **changes-mask** update-field system, not the 3.3.5 flat u32-index descriptor table. The client contains no descriptor tables and no field-name strings: each data struct has a generated reader pair, `ReadCreate` (full values, filtered by visibility flags) and `ReadUpdate` (a change mask, then only the changed values). Field names below are TrinityCore's (`wotlk_classic` UpdateFields.h) where the client's order, width, count and gating match; they are **[inferred]**. Offsets are byte offsets inside the client's data struct and are the stable identity of a field (the same offset is written by create and update).

## Serialization rules (from the readers)

**ValuesCreate** = `u32 size; u8 fieldFlags;` then each struct's create stream in type order. A create writes every field in declaration order with no masks; a field with a visibility flag is present only if `fieldFlags` has one of its flags. Flags seen in the readers: 0x01 Owner, 0x02 PartyMember, 0x04 UnitAll, 0x08 Empath (TrinityCore's UpdateFieldFlag: None=0, Owner=0x01, PartyMember=0x02, UnitAll=0x04, Empath=0x08). A dynamic array writes `u32 size` at its place in the order; its elements follow later in the stream (see each table's *elements (read after …)* row). Fixed arrays are written element by element; arrays of structs element by element, each element's members in order.

**ValuesUpdate** = `u32 size; u32 changedTypeMask;` then, for each struct whose type bit is set, a fresh bit stream: the change mask, then the changed values. For a struct with more than 32 mask bits the mask is a *block mask* (one bit per 32-bit block, `N` bits) followed by one 32-bit word for each set block; a struct with ≤ 32 bits writes a single word of exactly that many bits. Bits are MSB-first; `WriteBits(v, n)` puts bit n-1 of v first. Each value is read only if its own bit is set **and** every parent bit listed with it (usually bit 0, the struct's "any field in group" bit, and for arrays the array's parent bit). Dynamic arrays write `bits32 size`, then a per-element change mask (`size` bits, in 32-bit words), then the changed elements. A nested struct (array element) writes its own change mask and values. Byte-aligned values after bits mean the bit stream was flushed (TC `FlushBits()`).

Bit numbers below are absolute bits of the struct's change mask (block `b`, bit `k` = `32*b + k`). `nested#E.k` = bit k of a nested struct's own mask (E = the event index in the raw trace, see build/updatefields.raw.json).
